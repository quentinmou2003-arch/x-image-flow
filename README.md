## 云端整理界面（实验版 lab.15 · 2026-11-11）

在「本地库」打开「云端图库」，沿用现有 Google Drive 授权，分页浏览拾图原图库与子文件夹；可以复制单张原尺寸 PNG、按勾选顺序复制 1–20 张独立 PNG 到 QQ。云端预览按视口读取，离开附近区域释放缩略图，原文件只做最多 64 MB 的临时内存缓存，不整库落盘。首次预览仍需取回对应原文件，每张最多 40 MB，较大文件请到 Drive 单独处理。GIF 预览与本入口 PNG 复制为静态首帧。

可建立分类文件夹，为每个文件夹保存最多 2000 字规则与优先级；规则按 Google 账号、原图库隔离，保存在本机。此版尚未接入识图 API，不自动识别或执行分类，不产生模型费用。现在可勾选图片，手动「归入文件夹」：在目标位置建立快捷方式，原图和原文件名保留，不重复上传。重复操作跳过已创建的分类快捷方式；多张归类遇到失败时会报告完成数量，可重试。

仅访问当前授权的拾图原图库，不是整个 Google Drive 的通用文件管理器；支持的是桌面 Chrome 扩展界面，尚非独立 Windows 安装程序或手机应用。浏览、取图与复制调用 Drive，不调用识图模型。新流程已通过真实 Chromium＋模拟 Google API / 原生传输验证，真实账号浏览、复制及 QQ 粘贴待用户验收；原有上传功能保留。稳定版保持 2.3.22，Windows 助手仍为 1.3.1。


## 高清图批量复制修复（2.3.22 / lab.14 · 2026-11-10）

助手 1.3.1 修复把独立 PNG 的像素数累计后误判「整组图片尺寸过大」的问题。逐张准备、按原顺序复制，保持原分辨率和 PNG 字节，不自动缩图；保留每批 20 张、单张 40 MB、整批 200 MB，以及单张一亿像素 / 边长 32767 保护。GIF 总帧和拼接画布限制不变。整批成功才提交，失败保留勾选，避免漏复制。

更新扩展后也需运行新版 `native/安装小助手.cmd` 升级本机助手；只重新加载扩展不会更新已安装的 Windows 程序。旧助手触发此错误时会明确提示升级。Windows 原生协议测试已验证 20 张 3000×2000 PNG（合计 1.2 亿像素）逐张成功、文件名及字节不变；本次测试不向 QQ 发送消息。


## 作者、时间与描述命名（2.3.22 / lab.13）

后续图片统一使用 `作者_发推时间_推文描述_推文编号_图序.ext`，发推时间按北京时间；拼接结果以「拼接」结尾。云端原图保留真实文件格式与内容，批量文件复制为 PNG。描述缺失时使用「推文」，时间无法识别时标为「时间未知」。旧文件不批量改名；相同原图去重后沿用首次保存的名字，出处清单保留各条推文来源。

小助手安装器优先自动识别当前安装目录的扩展 ID，无法唯一确定时才手动填写；打开设置自动检测连接。X 点赞/书签接口在正常操作时学习，失效会提示回 X 操作。Google Drive 首次配置和登录授权仍需本人完成；连接后已有与后续收下的原图自动同步，断线任务保留并重试，Chrome 关闭期间暂停。


## lab.12 云盘连接修复 · 2026-11-06

修复 Chrome 后台将原生 fetch 作为普通对象方法调用时触发 Illegal invocation 的问题；此前该异常被统一显示成「云盘网络中断」，即使授权完成也无法确认账号。现绑定浏览器全局对象后发出请求，无须因此重新建立 Google 客户端。

88 项自动测试通过，新增全局调用上下文回归测试；真实 Chromium 使用未替换的原生 fetch，验证可到达拦截的 HTTP 端点、401 正确识别为授权问题、账号解析成功。原有四图上传模拟回归保留。真实用户授权和上传仍需重新加载后验收，不能把模拟结果视为已入云。

## 批量复制中拼接（2.3.22 / 实验版 lab.15）

在历史喜欢里开启「批量复制」，多图卡片会显示「独立图片 / 拼接一张」。普通图集逐张勾选；切片点击「拼接一张」，在预览中确认方向、顺序、片段和接缝，再点「确认拼接 · 加入批量」。疑似切片显示推荐，仍由你确认，不自动猜图。

一组确认的拼接图按一张输出计数，可以和单图、普通多图一起复制。确认会替换该组已选片段，沿用它们在队列中的首个位置；关闭预览不改变旧选择。「调整拼接」恢复上次参数；切回独立图片会移除该组拼接项，需要重新勾选片段。

每批最多 20 张输出 PNG，逐张处理，整批准备成功才写入剪贴板。导出固定使用确认预览的接缝，不再重新自动匹配。GIF / 视频不参与此批处理。需更新小助手到 1.3.1；整批 200 MB、每张 40 MB、单张一亿像素及边长 32767 的限制保留，独立 PNG 不再累计整批像素。QQ 接收形式待真实客户端试用。

批量拼接仅生成复制文件，不删除或替换本地库 / 云盘中的原片，不触发额外上传。

这是我的第一个 GitHub 项目。从自己在 X 上收图的需求出发，我借助 AI 辅助开发，逐步做出了图片瀑布流、卡牌图集、拼接和原尺寸 PNG 复制功能。

## 批量勾选复制（2.3.22 / 实验版 lab.15）

在「历史喜欢」的拾图界面点击顶部「批量复制」，卡片下方会展开每张照片的选择缩略图。逐张勾选，点击「复制所选 N 张」，然后切到 QQ 按 Ctrl+V。按勾选顺序放入多张独立 PNG，不自动发送，不改变 X 的点赞状态。

每批 1–20 张；切片也保留独立片段，可自行选需要的图片。切片可在预览确认后以拼接图加入队列；不包含 GIF 和视频；GIF 继续使用单独的「复制 GIF」。相同图片地址只选一次。支持清空、退出，失败保留选择；准备时切走页面会等待你回来再次点击复制。

**先重新运行 native/安装小助手.cmd，升级助手到 1.3.1**。每张最多 40 MB、整批最多 200 MB，解码像素也有上限。逐张准备以控制内存，完整准备后一次提交，避免失败只复制半套。QQ 可能显示为多张图片或文件，取决于 QQ 版本，请先试粘贴，不会自动发送。已验证真实 Windows 文件剪贴板，未验证真实 QQ 会话。

## 安装

目前通过本地加载安装，尚未上架 Chrome 网上应用店。

**[下载最新安装包](https://github.com/quentinmou2003-arch/x-image-flow/releases/latest)**：下载发布页中的 `x-image-flow-v2.3.22.zip` 并解压，加载包含 `manifest.json` 的目录即可。也可以按下面步骤下载完整源码安装。

1. 点击仓库上方 **Code → Download ZIP**，解压到一个固定目录。
2. 打开 Chrome 的 `chrome://extensions`，开启右上角的**开发者模式**。
3. 点击**加载已解压的扩展程序**，选择项目中的 **`extension` 文件夹**。
4. 刷新已登录的 X 页面，点击扩展图标，或页面右下角的「拾图 · 图片与视频」。

**Windows 多图小助手（安装一次）**：顶部「多图助手 → 复制插件 ID」，双击安装包 native 文件夹中的「安装小助手.cmd」，粘贴 ID，再点「检查连接」。无需管理员权限，按需启动，无联网或 QQ 自动操作。详情见 [小助手使用说明](extension/native/使用说明.md)。

升级时替换原目录中的文件，在扩展管理页点击重新加载，再刷新 X。请保留安装目录。

## 使用小贴士

- **广告过滤**：默认开启。顶部「广告已屏蔽」可切换；只过滤 X 明确标记的推广，不识别未标记的软广告。过滤作用于拾图图库。
- **点赞即复制**：默认开启，取消点赞不复制。普通多图复制成独立 PNG 文件列表，切片按检测结果自动拼接；QQ 的粘贴形式可能是图片或文件附件，需要试发确认。复制失败保留点赞，可用卡片「整组」重试。
- **防漏图**：默认「顺序收图」，卡片位置固定；底部进度表示已写入剪贴板，不代表已经发送 QQ。请先粘贴上一组再复制下一组。
- **收新图**：在首页切换「为你推荐 / 正在关注」。从历史收藏返回时，点击「回首页收新图」。
- **发 QQ**：点击「复制 PNG」，等复制成功后切到 QQ 的手机会话粘贴发送。插件不会自动发送消息。要保留文件，请保存后以文件形式发送。
- **看细节**：点击图片进入预览，滚轮或加减按钮缩放；放大后拖动，点击「适应」恢复全图。上一张、下一张固定在预览区两侧。
- **点赞和书签**：优先在当前页面调用 X 网页接口，不再新开推文标签页。首次使用按提示在 X 原网页正常操作一次；添加和取消操作分别学习，接口格式保存在本地，登录凭据仅留在页面内存。
- **拼接**：点图集的「拼接」，或选择 2–4 张图跨推文拼接。片段旁的 × 只从本次拼接移除图片。
- **PNG 的含义**：导出不会再做 JPEG 有损压缩，但将 JPEG 转成 PNG 不会恢复原来已经丢失的细节，文件通常更大。

## 当前限制

- 只处理 X 已经加载的内容，历史喜欢、书签需要随浏览逐步加载；不是一次性导出整个账号。
- 推文计数来自 X 已返回的数据，拿不到时显示「—」。X 页面和数据结构变化可能影响功能。
- 拼接不能还原原切片缺失的内容，也不能保证所有图集都能无缝对齐。
- 图库已取消 600 组限制；X 返回新内容时可继续加载。远处预览会卸载，但本轮记录仍占用内存，刷新可清空。
- 点赞、书签使用 X 未公开保证兼容的网页接口；接口变化后可能需要重新学习。当前接口测试使用模拟请求，真实 X 兼容性仍需试用验证。
- 视频播放依赖可取得的 MP4 地址。
- 这是独立的个人项目，与 X、QQ 无隶属关系。请尊重原作者的作品权利。

## 开发

扩展使用原生 JavaScript、CSS 和 Chrome Manifest V3，无构建步骤。

```text
extension/          可直接加载的扩展
  content.js        图库、交互和 X 页面提取
  ad-filter.js     推广数据与广告标记识别
  video-bridge.js   读取 X 已返回的媒体数据
  social-bridge.js  在当前 X 页面学习并调用互动接口
  social-protocol.js 操作格式校验与成功确认
  collection-flow.js 自动收图计划与切片判断
  native-copy.js    Windows Native Messaging 整组复制
  native/           轻量 Windows 小助手源码、安装及卸载
  native-menu.js    X 原菜单、后续弹窗与原帖定位
  background.js     后台任务和下载
  offscreen.js      图像解码与 PNG 输出
  stitch.js         拼接匹配
  icons/            像素 X 图标
tests/              可移植的基础测试
docs/FEATURE_STATUS.md 功能实现状态与验证范围
```

安装 Node.js 20 或更新版本后，在项目目录运行：

```sh
npm test
```

基础测试不依赖真实 X 账号；真实页面兼容性还需要在登录的 Chrome 中验证。
